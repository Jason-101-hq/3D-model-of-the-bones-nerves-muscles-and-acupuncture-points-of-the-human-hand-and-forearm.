开演前 3 分钟

  1. 起前端服务：cd arm-atlas && npm run dev，浏览器开 http://localhost:5173/。
  2. 窗口给到 1600×1000 以上。窗口太窄时右侧控制栏会挤压画布，预设机位的取景比例会跟着变。
  3. 等模型载入完（骨 29 / 肌 35 / 神经 30 / 体表 1，配 32 种颜色）。实测首次载入约 9 秒，别在这个空窗里开口。
  4. 先点一次「复位」，再点「整体视图」，确认机位回到起点。
  5. 把鼠标停在画布上晃一圈，看名称浮标出得来——出不来说明 WebGL 上下文已经掉了，刷新一次。
演示时不要用触控板双指缩放。缩放是对准指针位置的，触控板的惯性会让画面在讲完一句话之后还在动。 需要放大就用双击结构聚焦，需要机位就用右侧的视角按钮和情景预设——这两条路都是确定的、可以复现的。

这一版修了什么

  1. 「整体视图」装不下模型。它的相机距离只有 3.26 场景单位，而装下整个模型需要约 10.9—— 实测屏幕框 1607×1332 落在 1268×1000 的画布里，出框 18%，与讲稿里的「先看整体」不符。 改后出框率 0%。
  2. 每拍的「拍后动作」被漏掉。驱动循环里拍后还有一步（例如 1.2 那句讲完，才把肌肉重新打开， 好接 1.3 的「不必去掉肌肉，压薄就行」）。漏掉它，画面状态会从那一拍起一路分叉， 后面每一句「压到几成」都会变成什么都没发生——而录制过程本身不会报错。
  3. 帧时长会被静置停顿压缩。Chrome 的录屏会跳过与上一帧完全相同的帧，讲稿停顿期间一帧都不发。 若拿相邻帧的时间戳差当帧时长，38 秒的片段只会合成出 14.5 秒。改用「收到帧的时刻」计时后为 39.6 秒。
  4. 剥离之后，画布上的悬停与点击整体失效。「剥离 → 复原」会把结构的 raycast 写成 undefined，此后每一次射线检测都抛异常、界面却毫无提示。第三幕剥离起受影响， 已修（修复前 object.raycast is not a function ×20 个结构，修后 0）。
上面每一条都在改动之后重跑了完整核对（24/24 通过），本页的截图与录像都出自修好的这一版。 注意第 4 条：当时的核对是「全过」的——坏掉的功能恰好不落在任何一拍的核对点上。 核对只能证明它测到的那些东西是对的。
